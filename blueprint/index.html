Case study / Process supervision

The 90-minute stall
wasn't the rebuild.

A Python parent process waited for its child. The child tried to write to an unread stdout/stderr pipe. Once that pipe filled, neither process could advance. The supervisor appeared to be waiting on a slow rebuild; it was participating in a deadlock.

Incident-specific pipe capacity. A blocking write cannot progress without a reader freeing capacity.

ResolutionDrain while waiting

Continuously consume child stdout/stderr alongside process supervision. The corrected trace is illustrative, not captured production telemetry.

The trace uses deliberately discrete write/read events. Bytes accepted minus bytes consumed always equals the displayed occupancy. It does not simulate real-time throughput.
